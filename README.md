# Lupa — веб-аналитика на своём сервере

Сайт: https://getlupa.ru · Демо: https://demo.getlupa.ru · Код: https://github.com/cutover-team/lupa

Счётчик без cookie, события в ClickHouse, отчёты в браузере. Один бинарник на Go плюс ClickHouse.
Данные никуда не уходят: всё хранится на вашем VPS в России, баннер согласия на cookie не нужен.

## Что умеет (MVP)
- Посетители, визиты, просмотры, отказы, время на сайте, сравнение с прошлым периодом
- График по часам или дням, реалтайм за 30 минут и «сейчас на сайте»
- Страницы, заголовки, страницы входа, источники, UTM-кампании и остальные UTM
- Устройства, браузеры, ОС, разрешения экрана, язык
- События из кода страницы, цели по событию или пути, конверсии по визитам
- Воронки по последовательности шагов внутри визита
- Несколько сайтов, несколько пользователей, SPA-навигация
- Карта кликов: топ элементов по странице, глубина скролла, наложение тепловой карты прямо на страницу сайта
- Вебвизор: запись визитов через rrweb с маскированием полей, плеер в панели, хранение 30 дней

Чего пока нет: сегментов, геолокации, экспорта, разделения прав между пользователями.

## Карта кликов и вебвизор
Включаются атрибутами тега счётчика:

    <script async src="https://ваш-домен/lupa.js" data-site="1" data-clicks data-replay="10"></script>

- `data-clicks` — записывать клики: селектор элемента, текст, координаты в долях ширины страницы.
- `data-replay="10"` — записывать 10 % визитов для вебвизора. Дополнительно вебвизор нужно включить в настройках сайта, иначе сервер отбрасывает записи.
- `data-mask-text` — скрывать весь текст страницы в записях звёздочками. По умолчанию скрываются только поля ввода и элементы с `data-lupa-mask`; элементы с `data-lupa-block` заменяются заглушкой.

Тепловая карта рисуется самой страницей сайта: кнопка «Открыть карту на сайте» выдаёт ссылку с подписанным токеном на 2 часа,
lupa.js на странице забирает точки с сервера и накладывает canvas. Так карта работает с любым сайтом без iframe.

Для плеера вебвизора нужны библиотеки rrweb, они не хранятся в репозитории:

    make vendor   # скачает rrweb 1.1.3 и rrweb-player 0.7.14 в internal/web/static/vendor

Без них панель работает, но страница записи покажет подсказку.

## 152-ФЗ и вебвизор
Запись содержит структуру DOM и движения мыши. Поля ввода не записываются никогда, текст можно скрыть целиком.
IP не сохраняется, посетитель остаётся суточным хешем. Записи удаляются через 30 дней.
Клиенту всё равно стоит упомянуть запись сессий в политике обработки данных.

## Запуск на VPS за 10 минут
Нужен VPS с Docker, от 2 ГБ памяти, и домен с A-записью на него.

    git clone https://github.com/cutover-team/lupa.git && cd lupa
    cp .env.example .env        # задать домен, почту, пароль ClickHouse и зеркало реестра (Docker Hub из России часто недоступен)
    docker compose up -d --build
    docker compose logs -f lupa # дождаться «lupa слушает»

Откройте https://ваш-домен, создайте первого пользователя, добавьте сайт, скопируйте код счётчика.

## Код счётчика

    <script async src="https://ваш-домен/lupa.js" data-site="1"></script>

События и цели:

    lupa('lead_sent', {interest: 'audit'});

## Локальная разработка

    docker run -d --name ch -p 8123:8123 clickhouse/clickhouse-server:24.8
    go run ./cmd/lupa            # http://localhost:8080
    go test ./...

Переменные: LUPA_ADDR, LUPA_DATA_DIR, LUPA_CLICKHOUSE_URL, LUPA_CLICKHOUSE_DB, LUPA_CLICKHOUSE_USER,
LUPA_CLICKHOUSE_PASSWORD, LUPA_SECRET, LUPA_TRUST_PROXY, LUPA_BASE_URL, LUPA_TZ.

## Как считается
- Посетитель: хеш от секрета сервера, даты, сайта, IP и User-Agent. Меняется каждые сутки, cookie и localStorage не используются.
- Визит: события одного посетителя с перерывом не больше 30 минут. Сессии живут в памяти сервера.
- Отказ: визит с одним просмотром. Время на сайте: от первого до последнего события визита, с учётом времени на последней странице.
- Роботы отсекаются по User-Agent.
- События хранятся 24 месяца (TTL в таблице), затем удаляются.

## Схема
Таблица `events` в ClickHouse: одна строка на событие (`pageview`, `engage`, пользовательские).
Настройки, пользователи и цели в SQLite в каталоге данных.

## Безопасность
- Все пользователи видят все сайты: продукт для одной команды. Мультиарендность с правами появится позже.
- Счётчик принимает события только для существующих id сайтов.
- Перед Lupa должен стоять прокси с TLS (Caddy в compose), сервер читает IP из X-Forwarded-For.

## Сайт продукта и документы
- `site/` — статический сайт продукта без форм и сторонних счётчиков; отдаётся Caddy на домене `SITE_DOMAIN`. Перед публикацией замените `STATS_DOMAIN`, `DEMO_URL` и `REPO_URL`.
- `docs/152fz-client.md` — памятка клиенту: что Lupa хранит и что написать в политике.
- `docs/dpa-clause.md` — пункт о поручении на обработку для договора на управляемую установку.

## Публичное демо
`docker-compose.demo.yml` поднимает второй инстанс с базой `lupa_demo`. Переменная `LUPA_DEMO_USER` включает
автоматический вход под указанным пользователем, `LUPA_READONLY=true` запрещает любые изменения (все POST-запросы кроме входа получают 403).
Пользователя и сайт в демо создают один раз через /setup до включения режима, данные заливают в ClickHouse напрямую.
